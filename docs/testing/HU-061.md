# Verificación de HU-061

La PWA conserva una intención local de enviar (Estudiante) o publicar (Catedrático/Profesional externo verificado). Se revisan el formulario original y las cuatro categorías fotográficas mínimas antes de confirmar. La intención se guarda junto con los últimos datos en una transacción; no cambia a ENVIADA/PUBLICADA hasta recibir confirmación remota. Mientras esté pendiente se protege el contenido. Un rechazo definitivo conserva respuestas y motivo, habilita corrección y requiere una nueva confirmación con otra clave.

La cola procesa por inspección creación, datos, fotografías y acción final. Los intentos inciertos conservan petición y clave. La publicación HTTP tiene replay probado contra PostgreSQL/PostGIS, cálculo real del IC, historial y un solo evento. El IC no se calcula en Angular y se oculta el resultado previo al perder conexión.

## Comandos

Backend con Java 21 y Docker accesible:

```bash
cd sgp-api
java -version
mvn -version
mvn spotless:check
mvn -Dtest=Hu061Fase0IntegrationTest,IdempotenciaHttpFilterTest,PublicacionRealIcIntegrationTest,InspeccionControllerSecurityTest,TransicionInspeccionControllerSecurityTest test
```

Frontend con Node compatible (se recomienda Node 24, como las imágenes del proyecto):

```bash
cd sgp-client
npm ci
npm test
npm run lint
npm run format:check
npm run build
npx playwright install chromium
npm run test:pwa
```

El ejecutor PWA inicia un servidor local en 127.0.0.1:4173 con el contenido de `dist/sgp-client/browser`. Requiere compilar antes de ejecutarlo. En modo PWA sin `HU061_API_ORIGIN`, sus datos, usuario, fotografías y API son simulados explícitamente en `e2e/hu061`; no usa cuentas ni bases de desarrollo. Chromium ejecuta Angular, IndexedDB, CacheStorage y el service worker de producción reales. Con `HU061_API_ORIGIN`, el proxy reenvía `/api/` a Spring Boot real. La aceptación conectada posterior está documentada en [AUDITORIA_ACEPTACION_HU061.md](../../AUDITORIA_ACEPTACION_HU061.md); los comandos para preparar ese entorno desechable y sus regresiones se mantienen en la [guía HU-062](HU-062.md).

Escenarios de navegador:

- Manifiesto y control del worker; abrir y recargar sin red con traducciones y formulario disponibles; confirmar una publicación pendiente, cerrar la página, abrir otra y completar al reconectar.
- Entrega inmediata de referencia cacheada con actualización en segundo plano; recepción del aviso de nueva versión y opción de posponer; ausencia de respuestas de inspecciones en las cachés del worker.

Las pruebas locales adicionales cubren conservación de borradores al montar fotos/limpiar espacio, aislamiento entre cuentas, UUID remoto y versión preparada, intención única durable, bloqueo de edición, orden crear/datos/fotos/final, rechazo con nueva clave, bloqueo por foto no confirmada y referencias privadas por cuenta. El esquema de navegador es mínimo; no sustituye recorrer el formulario SIECA completo ni el flujo académico en staging.

## Prueba manual en el entorno persistente

Conservar el volumen PostgreSQL y usar el backend actualizado: Flyway aplica las migraciones pendientes y la siembra ya existente crea el formulario activo provisional cuando no hay ninguno. No aprobar académicamente esa calibración como parte de HU-061. Usar un Catedrático o un Profesional externo verificado para publicación y un Estudiante con curso/puente asignado para envío. Preparar la salida con conexión antes de desconectarse.

En `http://localhost:8088`, completar los campos y adjuntar evidencia de acceso, superestructura, subestructura y cauce. Desconectar, confirmar, comprobar “pendiente”, cerrar/abrir, reconectar y revisar estado, IC e historial. Revisar también rechazo y corrección, cambio de cuenta, sesión vencida y actualización con pendientes. Las pruebas automatizadas backend crean bases efímeras distintas de `sgp_db`.

## Límites y evidencia

El ADR-0007 documenta caché HTTP del index frente al app shell, SWR privado, sesión local, coordinación entre pestañas y elección de Playwright. La sincronización requiere una ventana abierta o volver a abrir la aplicación. La idempotencia mantiene la retención existente del servidor. Sin Web Locks no se promete exclusión local entre pestañas, aunque el servidor conserva idempotencia.

Se comprobaron la suite completa frontend de 1,273 pruebas; las 45 pruebas backend seleccionadas cubren el contrato y autorización, y la prueba HTTP de publicación confirma replay con IC real. Las dos pruebas de navegador pasaron. El build inicial se mantuvo por debajo de 500 KB incluso sin compresión (aproximadamente 443 KB; transferencia estimada aproximadamente 123 KB). No se certificaron instalación en un dispositivo físico, autonomía de ocho horas, carga real en 3G ni staging.
